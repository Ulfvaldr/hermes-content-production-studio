# Content Studio Hermes plugin

This profile-local plugin registers `content_studio_generate` in the `content_studio` toolset. The handler accepts the closed `content_studio.request.v1` envelope containing the eight original request fields, then invokes `runner.py` as a JSON subprocess. `runner.py` is the only component that imports `RunSubmissionService.submit(values)`.

Configure the target profile with `plugins.entries.content-studio.settings`: `studio_path`, `python_executable`, and `output_root` are required; `runner_path`, `pythonpath`, `subprocess_timeout_seconds`, and `max_retries` are optional. Hermes v0.21.6 supplies `task_id`, `session_id`, and `user_task` to a tool handler, not a plugin context. This plugin therefore captures its `PluginContext` in `register()` and reads settings with `ctx.get_config(...)`. Missing required configuration fails closed. Environment-variable configuration is retained only as an explicit standalone/test fallback, not as a way to duplicate credentials.

The handler returns `content_studio.result.v1`. Artifact validation is independent from final QA interpretation: a success is emitted only after it verifies the run directory, both production-pack files, safe paths under `output_root`, JSON readability, matching persisted `run_id`, and preserved request fields. `PASS` is success; `PASS WITH ISSUES` is success with `qa_warning`; `REVISION REQUIRED` is a completed but non-successful result with `FINAL_QA_REVISION_REQUIRED`; unknown or malformed QA status is a protocol error. `ARTIFACT_VALIDATION_FAILED` is reserved for invalid persisted outputs. It returns structured errors for validation, configuration, timeout, subprocess, protocol, and artifact failures. At most one retry is allowed, and only when process launch fails before the Studio can run. Timeout and nonzero subprocess exit are ambiguous after submission starts and are never retried.

The Studio subprocess receives a minimal allowlist of runtime variables (`PATH`, Windows loader/temp variables, and portable `HOME`/locale/temp variables), plus explicit `CONTENT_STUDIO_STUDIO_PATH`, `CONTENT_STUDIO_OUTPUT_ROOT`, and optional `PYTHONPATH`. Provider keys, Hermes tokens, shell state, and other inherited secrets are excluded. The subprocess boundary is not a credential injection mechanism.
